# V2.2_DETAIL_OPTIMIZATION_SPEC.md

# 同行旅 V2.2 细节优化需求文档

## 1. 文档目的

本文档用于指导 Claude Code 在 V2.1 优化完成后继续开发 V2.2 细节优化。

本次优化主要解决两个问题：

1. 旅行无法解散或退出。
2. 账单页每次进入都自动计算结算结果，加载成本高，且“添加账单”按钮位置不合理。

Claude Code 开发前必须先阅读：

```text
PROJECT_SPEC.md
CLOUD_DEV_GUIDE.md
V2_SPEC.md
V2-1_SPEC.md
```

然后基于当前已有代码继续开发。

------

## 2. 总体要求

### 2.1 禁止事项

本次优化禁止：

1. 重建项目。
2. 删除已有 V1 / V2 / V2.1 核心功能。
3. 大规模重构无关代码。
4. 引入新技术栈。
5. 使用 uni-app、Taro、Vue、React、TypeScript。
6. 使用自建服务器。
7. 在前端写入 appSecret、SecretId、SecretKey。
8. 信任前端传入的 openid。
9. 绕过云函数权限校验。

### 2.2 技术要求

继续使用：

```text
微信小程序原生开发
微信云开发
云函数
云数据库
JavaScript
WXML
WXSS
JSON
```

### 2.3 开发原则

1. 每次只完成一个阶段。
2. 不要一次性开发全部内容。
3. 所有涉及旅行数据修改的操作必须走云函数。
4. 所有涉及 `tripId` 的云函数必须校验当前用户是否属于该旅行。
5. 创建者权限和普通成员权限必须区分。
6. 删除、退出、解散类操作必须有二次确认。
7. 不要破坏已有创建旅行、加入旅行、账单、行程、待办、设置页逻辑。

## 3. 优化一：旅行管理功能

## 3.1 当前问题

当前小程序支持：

```text
创建旅行
加入旅行
```

但缺少：

```text
创建者解散旅行
普通成员退出旅行
```

这会导致：

1. 用户创建错旅行后无法清理。
2. 用户误加入旅行后无法退出。
3. 测试过程中会产生大量无用旅行。
4. 设置页缺少完整的旅行生命周期管理能力。

------

## 3.2 优化目标

在 `tripWorkspace` 的设置区增加旅行管理能力：

1. 创建者可以解散旅行。
2. 非创建者成员可以退出旅行。
3. 创建者不能通过“退出旅行”离开自己创建的旅行，只能选择“解散旅行”。
4. 普通成员退出后，不再能看到该旅行。
5. 旅行解散后，所有成员都不应再看到该旅行。
6. 操作前必须弹出二次确认。
7. 操作完成后跳转回首页，首页重新判断用户是否还有其他旅行。

------

## 3.3 权限规则

### 3.3.1 创建者

如果当前用户：

```js
openid === trip.creatorOpenid
```

则该用户是旅行创建者。

创建者可以：

```text
解散旅行
查看成员
复制邀请码
创建新旅行
加入其他旅行
切换旅行
```

创建者不显示：

```text
退出旅行
```

原因：创建者退出后旅行所有权不明确。V2.2 暂不做转让创建者。

------

### 3.3.2 普通成员

如果当前用户：

```js
openid !== trip.creatorOpenid
```

且属于：

```js
trip.memberOpenids
```

则该用户是普通成员。

普通成员可以：

```text
退出旅行
查看成员
复制邀请码
创建新旅行
加入其他旅行
切换旅行
```

普通成员不显示：

```text
解散旅行
```

------

## 3.5 数据处理策略

V2.2 推荐使用“软删除 / 状态标记”，不要直接物理删除全部数据。

原因：

1. 防止误删后无法恢复。
2. 避免删除 trips 后 expenses、itinerary、todos 产生孤儿数据。
3. 后续可以做回收站、恢复、历史归档。

------

## 3.6 trips 集合字段调整

建议给 `trips` 集合增加字段：

```js
{
  status: "active" | "dissolved",
  dissolvedAt: Date | null,
  dissolvedBy: string | null
}
```

默认新旅行：

```js
{
  status: "active",
  dissolvedAt: null,
  dissolvedBy: null
}
```

如果旧数据没有 `status` 字段，应视为：

```text
active
```

查询我的旅行时应只返回：

```text
status 不存在 或 status === "active"
```

不返回：

```text
status === "dissolved"
```

------

## 3.7 普通成员退出旅行的数据处理

普通成员退出时，不删除旅行，只从 `memberOpenids` 中移除当前用户 openid。

退出后：

1. 当前用户不再属于该旅行。
2. `getMyTrips` 不再返回该旅行。
3. 当前用户不能再通过旧 `tripId` 访问该旅行。
4. 该用户之前创建的账单、行程、待办暂时保留。
5. 结算逻辑中需要注意历史账单参与人可能包含已退出成员。

### 3.7.1 关于历史账单的处理

V2.2 暂不处理复杂账务归档。

规则：

1. 成员退出不会自动删除其历史账单。
2. 成员退出不会自动修改历史账单参与人。
3. 如果该成员曾参与账单，结算结果中仍可能出现该成员。
4. 后续版本可以单独做“成员退出前结算检查”。

为了避免误解，退出确认文案应提示：

```text
退出不会删除你已经创建或参与的历史账单。
```

## 3.8 新增云函数：dissolveTrip

### 3.8.1 云函数名

```text
dissolveTrip
```

### 3.8.2 功能

创建者解散旅行。

### 3.8.3 输入

```js
{
  tripId: string
}
```

### 3.8.4 校验

1. `tripId` 不能为空。
2. 当前用户必须属于该旅行。
3. 当前用户必须是 `creatorOpenid`。
4. 旅行必须存在。
5. 旅行未被解散。
6. openid 必须从 `cloud.getWXContext().OPENID` 获取，不能信任前端。

### 3.8.5 更新逻辑

将 `trips` 中对应记录更新为：

```js
{
  status: "dissolved",
  dissolvedAt: new Date(),
  dissolvedBy: openid,
  updatedAt: new Date()
}
```

### 3.8.6 返回格式

成功：

```js
{
  success: true,
  data: {},
  message: ""
}
```

失败：

```js
{
  success: false,
  data: null,
  message: "错误原因"
}
```

## 3.13 前端跳转逻辑

解散或退出成功后：

1. 显示成功提示。
2. 清理当前页面中与该 trip 相关的状态。
3. 跳转到首页。
4. 首页重新执行 `getMyTrips`。
5. 如果还有其他旅行，按既有逻辑自动进入最近旅行。
6. 如果没有其他旅行，停留首页。

建议使用：

```js

  url: '/pages/index/index'
})
```

## 4. 优化二：账单界面调整

## 4.1 当前问题

当前账单 tab 中，结算结果和建议转账可能每次进入账单页面都自动计算。

问题：

1. 实际使用中，用户通常不是每次进账单都需要结算。
2. 一般只会每天结算一次，或者旅行结束时结算。
3. 自动结算会增加云函数调用次数。
4. 账单多时会增加加载时间。
5. 添加账单按钮如果放在页面底部，账单一多需要下滑很久，交互体验差。

------

## 4.2 优化目标

账单 tab 改为：

1. 进入账单 tab 时只加载账单列表。
2. 不自动调用 `calculateSettlement`。
3. 增加一个“计算结算”按钮。
4. 用户点击按钮后才调用 `calculateSettlement`。
5. 结算结果计算完成后显示在账单 tab 中。
6. 如果用户新增账单，应标记当前结算结果可能已过期。
7. 添加账单按钮移动到页面上方或固定在账单 tab 顶部，不再放在账单列表底部。

------

建议布局：

## 4.4 添加账单按钮位置

### 4.4.1 当前问题

如果“添加账单”按钮在账单列表最下方，账单一多，用户每次都要滑到底部才能添加。

### 4.4.2 新要求

“添加账单”按钮必须放在账单 tab 上方明显位置。

推荐位置：

1. 账单 tab 顶部操作区。
2. 总消费卡片旁边。
3. 或作为右上角按钮。

不要放在账单列表底部作为唯一入口。

------

## 4.5 计算结算按钮

### 4.5.1 按钮文案

使用：

```text
计算结算
```

或：

```text
查看结算
```

推荐：

```text
计算结算
```

因为它明确表示需要触发计算。

### 4.5.2 交互逻辑

用户点击“计算结算”后：

1. 设置 `settlementLoading = true`。
2. 调用 `calculateSettlement(tripId)`。
3. 返回后显示结算结果。
4. 设置 `settlementLoaded = true`。
5. 设置 `settlementLoading = false`。
6. 如果失败，显示错误提示和重试按钮。

------

## 4.6 账单 tab 加载逻辑调整

### 4.6.1 当前逻辑需要改掉

如果当前代码在进入账单 tab 时执行：

```text
loadExpenses()
loadSettlement()
```

需要改为：

```text
loadExpenses()
```

不要自动调用：

```text
loadSettlement()
```

### 4.6.2 新逻辑

进入账单 tab：

```text
只加载账单列表
不计算结算
```

用户点击“计算结算”：

```text
调用 calculateSettlement
展示结果
```

------

## 4.7 结算结果状态设计

建议在 `tripWorkspace.js` 中维护：

```js
data: {
  settlement: null,
  settlementLoading: false,
  settlementLoaded: false,
  settlementError: '',
  settlementStale: false
}
```

字段说明：

| 字段              | 说明                                 |
| ----------------- | ------------------------------------ |
| settlement        | 当前结算结果                         |
| settlementLoading | 是否正在计算                         |
| settlementLoaded  | 是否已经手动计算过                   |
| settlementError   | 结算失败信息                         |
| settlementStale   | 账单变化后，当前结算结果是否可能过期 |

------

## 4.8 结算结果展示规则

展示顺序：

```text
如果 settlementLoading:
  显示“正在计算结算结果...”

否则如果 settlementError:
  显示错误信息和重试按钮

否则如果 settlementLoaded && settlement:
  显示结算结果

否则:
  显示提示：“点击计算结算，查看当前账单的分摊结果”
```

------

## 4.9 账单变化后的处理

如果用户新增账单、删除账单或编辑账单，则当前已有结算结果可能过期。

处理规则：

1. 添加账单成功返回后，刷新账单列表。
2. 如果此前已经计算过结算，则设置：

```js
settlementStale: true
```

1. 结算区域显示提示：

```text
账单已更新，当前结算结果可能不是最新。请重新计算。
```

1. 用户再次点击“计算结算”后：
   - 重新调用 `calculateSettlement`
   - 更新结算结果
   - 设置 `settlementStale: false`

------

## 4.10 账单列表空状态

如果账单列表为空：

1. 显示：

```text
暂无账单
```

1. 仍然显示顶部“添加账单”按钮。
2. “计算结算”按钮可以置灰，或点击后提示：

```text
暂无账单，暂不需要结算
```

推荐：

```text
账单为空时禁用“计算结算”按钮
```

## 阶段 1：旅行解散和退出云函数

2. 新增 `leaveTrip` 云函数。
3. 修改 `getMyTrips`，过滤已解散旅行。
4. 修改 `getTripDetail`，拒绝访问已解散旅行。

5. 操作成功后 `wx.reLaunch` 到首页。

完成标准：

1. 创建者只能看到解散旅行。
2. 普通成员只能看到退出旅行。
3. 确认前不会直接执行危险操作。

4. 增加结算 loading / error / loaded 状态。

完成标准：

1. 进入账单 tab 只加载账单列表。
2. 点击“计算结算”后才显示结算结果。
3. 结算失败时有错误提示和重试。
