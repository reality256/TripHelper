# 2. 版本背景

V3.2 已基本完成同行旅的主要业务能力，包括：

* 旅行创建与加入
* 成员管理
* 行程管理
* 地图选点与路线相关功能
* 账单记录与编辑
* 入账、退款相关金额计算
* 预算管理
* 待办管理
* 账单结算

当前版本的主要问题已经不再是功能缺失，而是随着页面和功能逐渐增加，项目中形成了多套局部样式规则。

目前主要存在以下问题：

1. 同一种语义使用不同颜色。
2. 相同类型卡片采用不同内边距和圆角。
3. 页面标题、分区标题和核心金额缺少明确的字号层级。
4. 全局 CSS 变量已经定义，但大量页面仍然硬编码颜色。
5. 多个页面重复实现 loading、成员选择器等样式。
6. 新页面与旧页面在视觉密度和组件风格上存在明显差异。
7. 页面级 WXSS 逐渐失去统一约束，后续维护成本持续上升。
8. 部分视觉元素虽然功能正常，但加载态、空状态、禁用态和错误态不够统一。

因此，V4.0 不再继续堆叠大型业务功能，而是集中建立稳定的设计系统，统一现有页面，并为后续版本提供明确的 UI 开发规范。

# 4. 非目标范围

以下内容不属于 V4.0：

1. 不新增新的一级功能模块。
2. 不重写整个小程序。
3. 不迁移至 Taro、uni-app 等跨端框架。
4. 不引入第三方大型 UI 组件库。
5. 不重构云函数架构。
6. 不修改数据库字段。
7. 不调整账单和预算业务规则。
8. 不重新设计地图路线算法。
9. 不增加暗色模式。
10. 不将所有页面强制改造成自定义组件。
11. 不因为样式统一而大规模修改 JavaScript 业务代码。
12. 不删除疑似旧页面，除非已经确认没有任何路由或代码引用。
13. 不使用 Emoji 充当正式功能图标。
14. 不进行与本版本无关的代码格式化或目录重构。

# 5. 开发前置检查

在修改任何代码之前，必须先完成一次项目实际使用情况检查。

## 5.1 页面路由检查

检查：

* `app.json` 中注册的页面
* `tabBar` 或自定义底部导航配置
* `wx.navigateTo`
* `wx.redirectTo`
* `wx.reLaunch`
* `wx.switchTab`
* WXML 中的跳转事件
* 页面之间的引用关系

将页面划分为：

| 类型  | 定义                 | V4 处理方式        |
| --- | ------------------ | -------------- |
| A 类 | 当前用户可以正常访问的正式页面    | 必须纳入统一         |
| B 类 | 兼容旧流程但仍存在调用的页面     | 保持功能，仅做必要统一    |
| C 类 | 无路由、无跳转、无引用的疑似废弃页面 | 记录，不在 V4 中直接删除 |

Claude Code 必须先输出页面分类结果，再开始修改。

## 5.2 样式依赖检查

检查以下内容：

* 页面是否依赖 `app.wxss` 的全局类
* 是否存在同名 class 被页面 WXSS 覆盖
* 是否存在组件样式隔离
* 是否存在 `styleIsolation`
* 是否存在行内样式
* 是否存在动态 class
* 是否存在由 JavaScript 动态计算的颜色或宽度
* 是否存在依赖特定 DOM 层级的选择器

不得仅通过全文搜索替换颜色值完成重构。

## 5.3 基准截图

修改前至少保留以下页面截图：

* 首页
* 旅行工作台的行程页
* 旅行工作台的账单页
* 旅行工作台的待办页
* 旅行工作台的设置页
* 已设置预算状态
* 未设置预算状态
* 账单详情
* 成员管理
* 结算页面
* 地图全览页面

截图用于修改后的视觉对照，不要求引入自动化截图系统。

# 6. V4 设计原则

## 6.1 视觉方向

整体视觉继续采用：

* 低饱和青绿色作为品牌色
* 浅灰绿色页面背景
* 白色卡片
* 轻量阴影
* 较大的圆角
* 清晰的金额层级
* 适度留白
* 克制的装饰元素

视觉关键词：

> 清晰、轻量、可靠、协作、旅行感、不过度装饰。

## 6.2 微信小程序适配原则

1. 页面尺寸继续使用 `rpx`。
2. 点击区域原则上不小于 `88rpx × 88rpx`。
3. 固定底部操作区需要适配安全区域。
4. 不依赖 hover 作为唯一反馈。
5. 按钮必须处理微信原生 `button::after` 边框。
6. 输入框、文本域和 picker 应保留原生交互能力。
7. 不使用复杂模糊、滤镜和高成本动画。
8. 动画优先使用 `transform` 和 `opacity`。
9. 不在长列表中使用大面积重阴影。
10. 不因 UI 调整显著增加 `setData` 数据量。
11. 自定义组件需注意样式隔离，不得假设 `app.wxss` 一定能覆盖组件内部样式。
12. CSS 变量必须提供兼容性回退值。

示例：

```css
color: var(--color-primary, #2A9D8F);
```

# 7. 设计 Token 规范

需要新增：

```text
spec/DESIGN_TOKENS.md
```

同时在 `app.wxss` 中建立对应基础变量。

## 7.1 颜色 Token

建议在 `app.wxss` 中使用以下定义：

```css
page {
  --color-primary: #2A9D8F;
  --color-primary-pressed: #23877B;
  --color-primary-light: #E8F5F3;

  --color-bg-page: #F5F7F6;
  --color-bg-card: #FFFFFF;
  --color-bg-disabled: #F2F3F3;

  --color-text-primary: #1A1A1A;
  --color-text-secondary: #666666;
  --color-text-tertiary: #999999;
  --color-text-disabled: #B8B8B8;

  --color-border-light: #F0F0F0;
  --color-border-default: #E8E8E8;
  --color-border-strong: #D0D0D0;

  --color-danger: #E74C3C;
  --color-danger-light: #FDEDEC;

  --color-success: #27AE60;
  --color-success-light: #EAF7EF;

  --color-warning: #E67E22;
  --color-warning-light: #FFF4E8;

  --color-stale-bg: #FFF8E1;
  --color-stale-text: #B8860B;
}
```

## 7.2 红色语义处理

项目中的危险色统一为：

```text
#E74C3C
```

原有：

```text
#E8685A
```

不再作为正式危险色使用。

以下场景统一使用危险色：

* 删除
* 超预算
* 负向结算金额
* 错误提示
* 清除预算
* 移除成员
* 不可逆操作

如果“入账金额”和“退款金额”继续按照现有产品规则显示为红色，应在设计文档中单独定义业务语义名称，例如：

```css
--color-income: #E74C3C;
```

即使当前值与危险色相同，也必须区分语义，避免后续修改危险色时误伤金额展示。

## 7.3 分割线层级

统一使用三档：

| Token | 颜色        | 场景            |
| ----- | --------- | ------------- |
| 轻分割   | `#F0F0F0` | 卡片内部弱分隔       |
| 默认边框  | `#E8E8E8` | 输入框、切换控件、普通边框 |
| 强边框   | `#D0D0D0` | 复选框、虚线区域、强调边界 |

不得继续随意增加近似灰色。

## 7.4 间距规范

间距尽量采用 4rpx 的整数倍。

| 场景        |                规范 |
| --------- | ----------------: |
| 页面水平边距    |           `32rpx` |
| 页面顶部常规间距  |           `32rpx` |
| 表单页顶部间距   |           `40rpx` |
| 页面主要区块间距  |           `32rpx` |
| 卡片间距      |           `20rpx` |
| 卡片内部元素间距  | `16rpx` 或 `20rpx` |
| 标准卡片内边距   |     `28rpx 32rpx` |
| 紧凑列表卡片内边距 |     `24rpx 28rpx` |
| 小型标签内边距   |      `8rpx 16rpx` |

页面不得自行创造新的卡片内边距标准，除非有明确布局原因。

## 7.5 圆角规范

| 类型     |                圆角 |
| ------ | ----------------: |
| 标准卡片   |           `20rpx` |
| 输入框    |           `14rpx` |
| 提示条、横幅 |           `12rpx` |
| 小型标签   | `10rpx` 或 `12rpx` |
| 分段切换控件 |           `28rpx` |
| 主按钮    |           `48rpx` |
| 单选控件   |             `50%` |
| 多选控件   |            `8rpx` |

说明：

* 卡片统一使用 `20rpx`。
* 横幅、输入框、标签不是卡片，不强制使用 `20rpx`。
* 行程视图切换和待办筛选属于同类分段控件，统一为 `28rpx`。
* 单选使用圆形，多选使用圆角方形。

## 7.6 字号层级

| 类型         |                字号 | 建议字重 |
| ---------- | ----------------: | ---: |
| 页面主标题      |           `40rpx` |  600 |
| 重要卡片标题     |           `32rpx` |  600 |
| Section 标题 |           `28rpx` |  600 |
| 次级标题       |           `26rpx` |  500 |
| 正文         |           `28rpx` |  400 |
| 辅助文字       |           `24rpx` |  400 |
| 标签、说明      |           `22rpx` |  400 |
| 核心汇总金额     |           `56rpx` |  700 |
| 详情页主金额     |           `64rpx` |  700 |
| 辅助金额       | `40rpx` 或 `44rpx` |  600 |

金额字号不再按照页面随意设置，而按照信息层级设置：

* 汇总卡片：`56rpx`
* 详情页唯一主金额：`64rpx`
* 辅助数据：`40rpx` 或 `44rpx`

原 `68rpx` 详情金额调整为 `64rpx`。

## 7.7 控件高度

| 控件     |      高度 |
| ------ | ------: |
| 主按钮    | `96rpx` |
| 次按钮    | `88rpx` |
| 输入框    | `88rpx` |
| picker | `88rpx` |
| 分段切换   | `64rpx` |
| 最小点击区域 | `88rpx` |

## 7.8 阴影规范

标准卡片使用极轻阴影：

```css
box-shadow: 0 4rpx 16rpx rgba(26, 26, 26, 0.04);
```

规则：

* 普通列表卡片不得使用重阴影。
* 同一页面不允许出现多种卡片阴影。
* 弹层和悬浮操作区可以采用更明显阴影，但需独立定义。
* 不使用大面积彩色阴影。

# 8. 全局基础样式

## 8.1 全局类命名

新增加的公共样式统一使用 `ui-` 前缀，避免与现有页面 class 冲突。

建议包括：

```text
.ui-page
.ui-card
.ui-card--compact
.ui-section-title
.ui-text-secondary
.ui-text-tertiary
.ui-divider
.ui-btn
.ui-btn--primary
.ui-btn--secondary
.ui-btn--danger
.ui-input
.ui-tag
.ui-empty
.ui-loading
.ui-loading-spinner
```

## 8.2 全局类职责

`app.wxss` 只负责：

* Token
* 页面基础背景
* 通用排版
* 基础卡片
* 基础按钮
* 基础输入框
* 状态标签
* loading
* 空状态
* 通用分割线

`app.wxss` 不负责：

* 某个页面的专属布局
* 某个业务模块的复杂定位
* 地图布局
* 时间线节点位置
* 账单详情特殊结构
* 页面专属动画

页面专属布局继续保留在对应页面 WXSS 中。

## 8.3 避免宽泛选择器

不得新增可能误伤页面的宽泛规则，例如：

```css
view {
  box-sizing: border-box;
}

text {
  color: #333;
}

button {
  background: ...;
}
```

如果需要统一按钮，应通过明确 class 实现。

允许保留必要的原生按钮边框处理：

```css
.ui-btn::after {
  border: none;
}
```

# 9. 卡片系统

## 9.1 标准内容卡片

适用于：

* 表单容器
* 预算详情
* 结算概览
* 账单详情信息
* 页面主要内容块

规范：

```css
.ui-card {
  padding: 28rpx 32rpx;
  border-radius: 20rpx;
  background: var(--color-bg-card, #FFFFFF);
  box-shadow: 0 4rpx 16rpx rgba(26, 26, 26, 0.04);
}
```

## 9.2 紧凑列表卡片

适用于：

* 行程列表
* 账单列表
* 待办列表
* 成员列表
* 转账列表

规范：

```css
.ui-card--compact {
  padding: 24rpx 28rpx;
}
```

## 9.3 卡片使用限制

* 同一种卡片在不同页面应保持相同视觉密度。
* 不允许通过页面覆盖将卡片圆角改成 `12rpx` 或 `16rpx`。
* 横幅、提示条和日期选择器不属于卡片系统。
* 空预算提示区域可以继续使用提示区样式，但不得命名为 card。

# 10. 按钮系统

## 10.1 主按钮

用于当前页面最主要操作：

* 创建旅行
* 保存账单
* 保存行程
* 保存预算
* 确认结算

规范：

* 品牌色背景
* 白色文字
* 高度 `96rpx`
* 圆角 `48rpx`
* 一个页面原则上只出现一个最强主操作

## 10.2 次按钮

用于：

* 取消
* 返回
* 次要跳转
* 非核心操作

采用：

* 浅色背景或描边
* 品牌色文字
* 不与主按钮争夺视觉层级

## 10.3 危险按钮

用于：

* 删除账单
* 删除行程
* 移除成员
* 清除预算
* 删除旅行

必须满足：

1. 使用危险色。
2. 操作文字明确，不使用模糊词语。
3. 不可逆操作继续使用确认弹窗。
4. 不允许仅使用红色图标而没有文字或辅助说明。
5. 危险按钮不应与主按钮拥有完全相同的视觉权重，除非处于二次确认弹层。

## 10.4 禁用状态

禁用按钮必须同时体现：

* 背景变灰
* 文字变浅
* 不响应点击
* 不显示按压态

不得仅通过降低透明度处理所有禁用状态。

# 11. 表单系统

## 11.1 输入框

统一：

* 高度 `88rpx`
* 圆角 `14rpx`
* 默认边框 `#E8E8E8`
* 背景可使用浅灰
* 左右内边距统一
* placeholder 使用三级文字色
* focus 状态使用品牌色边框

## 11.2 输入校验

V4 不改变原有业务校验逻辑，但统一错误展示：

* 错误信息放在对应控件下方
* 错误文字使用危险色
* 输入框边框同步变为危险色
* 不仅依赖 toast 表达字段错误
* toast 仍可用于提交级错误

## 11.3 金额输入

继续遵循现有规则：

* 必须为正数
* 最多两位小数
* 禁止非法字符
* 提交前再次校验
* 不允许仅依赖键盘类型保证输入合法

本版本只统一视觉反馈，不改变金额计算逻辑。

## 11.4 成员选择

统一规则：

* 单选：圆形选择控件
* 多选：`8rpx` 圆角方形选择控件
* 选中状态使用品牌色
* 未选中边框使用强边框色
* 整个成员行可点击，不仅点击小型复选框
* 禁用成员需要同时显示禁用原因或状态

# 12. Loading、空状态和错误状态

## 12.1 Loading

目前多个页面重复定义 loading spinner。

V4 中：

1. 将通用 spinner 移至 `app.wxss`。
2. 全项目只保留一份 `@keyframes` 定义。
3. 页面通过公共 class 使用。
4. 地图等特殊 loading 可以保留页面专属布局，但 spinner 本体应复用。
5. loading 时不得重复触发提交按钮。

## 12.2 空状态

以下页面需要统一空状态：

* 暂无行程
* 暂无账单
* 暂无待办
* 暂无成员
* 暂无结算记录
* 暂未设置预算
* 暂无地图路线

统一结构：

* 简洁图形或图标
* 主说明文字
* 可选辅助说明
* 可选操作按钮

不得使用 Emoji 作为正式空状态图标。

## 12.3 错误状态

请求失败时：

* 不得长期保持 loading
* 显示明确错误信息
* 提供重试入口
* 保留已有数据时，不应直接清空页面
* 网络错误与无数据状态不得混为一谈

## 12.4 刷新状态

页面数据刷新时：

* 如果已有内容，尽量保留当前内容
* 使用轻量刷新状态，不重新展示整页空白 loading
* 防止连续点击导致重复请求
* 不修改已有刷新时机和业务同步逻辑，除非发现明确缺陷并单独报告

# 16. 动效规范

V4 只允许轻量动效：

* 按钮按压反馈
* Tab 切换
* 筛选状态变化
* loading spinner
* 弹层进入和退出
* 进度条变化

建议时长：

| 类型   |            时长 |
| ---- | ------------: |
| 按压反馈 | `100ms–150ms` |
| 状态切换 | `160ms–200ms` |
| 弹层   | `200ms–240ms` |
| 进度变化 | `200ms–300ms` |

限制：

* 不增加大面积弹跳动画。
* 不增加长时间循环动画。
* 不使用会明显影响低端设备性能的滤镜。
* 不因动画延迟实际操作结果。
* 遵循微信小程序页面切换本身的交互习惯。

# 17. 兼容性与安全区域

固定底部区域需要适配：

```css
padding-bottom: calc(24rpx + env(safe-area-inset-bottom));
```

必要时提供兼容写法：

```css
padding-bottom: calc(24rpx + constant(safe-area-inset-bottom));
padding-bottom: calc(24rpx + env(safe-area-inset-bottom));
```

检查设备：

* 小屏 iPhone
* 带底部安全区域的 iPhone
* 常见 Android 全面屏
* 微信开发者工具标准模拟器

不得因为安全区适配导致：

* 底部按钮过高
* 内容无法滚动到底部
* 底部导航遮挡内容
* 出现重复 padding

Claude Code 每完成一个阶段，必须按照以下格式汇报：

```markdown
## 本阶段完成内容

- ...

## 修改文件

- `path/to/file`
- `path/to/file`

## 未修改内容

- 业务逻辑：
- 数据结构：
- 云函数：
- 权限规则：

## 需要重点检查

1. ...
2. ...

## 手动测试步骤

1. ...
2. ...

## 已知风险

- ...

## CHANGELOG

- 已更新 / 未更新及原因
```

完成汇报后立即停止，不得继续下一阶段。

# 24. 版本完成定义

只有同时满足以下条件，V4.0 才可以视为完成：

1. 设计 Token 已建立并落地。
2. 所有正式使用页面已完成视觉检查。
3. 核心页面已完成统一。
4. 重复 loading 样式已清理。
5. 危险色已统一。
6. 卡片体系已统一。
7. 标题和金额层级已统一。
8. 空状态、加载态和错误态已统一。
9. 微信开发者工具无新增错误。
10. 至少完成一次真机测试。
11. 所有现有核心业务流程通过回归测试。
12. `CHANGELOG.md` 已更新。
13. `V4_UI_REVIEW.md` 已完成。
14. 未引入未经确认的新功能。
15. 未修改云端数据和核心计算规则。

# 25. 后续版本边界

V4.0 完成后，再根据实际使用反馈考虑：

* V4.1：单页面视觉细节雕琢
